# ADR-001: Один Next.js-сервис, снимки договоров и демонстрационный провайдер

Статус: принято. Дата: 2026-10-13.

## Контекст

Нужен локально запускаемый MVP с рабочей демонстрацией, защищёнными ссылками, корректной кириллицей и возможностью последующего перехода к PostgreSQL и настоящей ЭЦП.

## Варианты

1. Next.js Route Handlers и SQLite / Prisma, отдельные прикладные функции.
2. Отдельный backend, PostgreSQL и инфраструктура уже в MVP.
3. Статический UI с браузерным хранилищем и имитацией backend.

## Решение и причины

Выбран первый вариант: минимальная инфраструктура, настоящая база, серверная авторизация, транзакции. Только SigningProvider имеет интерфейс, потому что замена провайдера прямо указана в требованиях. Repository-функции обслуживают общие выборки; интерфейс для каждого CRUD не создаётся.

Отправка сохраняет неизменяемую строку снимка и SHA-256. Любое редактирование отправленного договора запрещается; изменение создаёт новый договор. Сроки ссылок вычисляются на запросе без фонового cron.

Для повторного копирования ссылки администратором токен дополнительно хранится в AES-256-GCM под отдельным ключом. Альтернатива «показывать URL только однажды» ухудшает требуемый сценарий повторного копирования. Сессионные токены шифровать не требуется, поскольку их восстановление не нужно.

PDFKit выбран для серверного потокового текста, кириллицы через встраиваемый Noto Sans и A4 без внешнего браузера. PDF генерируется по запросу из снимка; личные документы не размещаются в статической директории.

## Последствия и риски

Нужен один постоянный локальный диск. SQLite ограничивает масштабирование; JSON-строки менее удобны для сложной аналитики. Владелец базы способен менять данные, снимок не даёт юридического доказательства. Потеря encryption key делает восстановление сохранённых URL невозможным. Модуль ЭЦП в будущем потребует расширения модели, а не только замены провайдера.

## Дальнейшая работа

PostgreSQL, юридический и security review, настоящая ЭЦП, production-деплой и защищённое архивирование PDF — отдельные этапы ROADMAP.
