# ADR-002: Бесплатный Render и внешний PostgreSQL

Статус: принято для подготовки; живое размещение требует проверки. Дата: 2026-10-13.

## Контекст

Владелец запросил сервер, бесплатный домен и внешние ссылки, затем уточнил: все ресурсы должны быть бесплатными. SQLite на эфемерной файловой системе Render Free теряется при рестарте и не подходит для сохраняемых договоров.

## Варианты

- Платный Render с постоянным SQLite-диском — отклонён из-за требования нулевой стоимости.
- Render Free со SQLite в файловой системе — отклонён: потеря данных и выданных ссылок.
- Render Free + Neon Free PostgreSQL — выбран: сохраняется Node.js/Next.js стек, данные отделены от эфемерного сервиса.
- Переход на Workers/D1 — потребовал бы смены runtime, PDF и транзакционных решений, избыточен для этой задачи.

## Решение

Сохранить SQLite для локальной разработки. Генерировать PostgreSQL-schema из тех же моделей, использовать отдельные PostgreSQL-миграции и direct TLS URL для миграций. Облако собирается через build:cloud; публичный origin берётся из переменных Render, чтобы ссылки не ссылались на localhost.

Транзакции договоров переведены в Serializable с тремя ограниченными повторами ошибки P2034. Это необходимо при гонке отзыва/замены ссылки и sign в PostgreSQL: проверка действительности ссылки и изменение договора должны наблюдать согласованное состояние. Повторный запрос перечитывает состояние и отказывает при отзыве/подписании.

## Последствия

Нужен аккаунт Neon и его подключение к серверному приложению. Бесплатный Render засыпает; публичный первый запрос может ждать. PostgreSQL-миграции и конкурентное поведение должны проверяться на реальном облаке. Две базы изолированы; перенос localhost-договоров не происходит автоматически. Платные ресурсы и автопереход на платные планы запрещены.
