# Qutty Qonaq: бренд, языки и ручной календарь

## Использование

Переключатель РУС / ҚАЗ / EN доступен в каталоге, входе, кабинете и интерфейсе ознакомления. Выбор хранится в cookie `qutty-language` на год (`SameSite=Lax`), применяется к первому серверному отображению, `html lang` и интерфейсным датам. Неизвестное значение означает русский язык. Фотографии и адресные имена сохранены. Договор, условия, персональные реквизиты, пользовательские названия/описания и PDF не переводятся автоматически: это отдельные документы и данные, а не интерфейс. Нативные сообщения браузера зависят от языка браузера. Неизвестные сообщения сервера остаются исходными. Переводы находятся в `src/lib/translations.json`.

Логотип из предоставленного изображения подготовлен без слогана «Сенің жайлы орның» и его декоративных элементов; исходный файл в Downloads не изменён. На сайте используется `public/brand/qutty-qonaq.png`. Карточка при наведении/фокусе слегка поднимается, страница квартиры плавно появляется. `prefers-reduced-motion` отключает движение.

## Ручная занятость

В кабинете откройте **Занятость**. Квартира должна быть добавлена из каталога в ваши активные объекты. Укажите первый и последний занятые дни и статус **Занято** или **Забронировано**. Оба дня включены. Например, при выезде утром 5 ноября и возможности нового заезда 5 ноября последним занятым днём укажите 4 ноября. Для исправления снимите отметку и добавьте правильный период.

Календарь размещён под галереей. Неотмеченные дни означают **Нет отметки**, а не подтверждённую доступность. Пока владелец не внесёт реальные периоды, все даты остаются без отметки. Пересекающиеся периоды разрешены; при пересечении «Занято» имеет приоритет над «Забронировано». Изменение/подписание договора не меняет календарь автоматически. Онлайн-бронирования, оплаты и синхронизации внешних календарей нет. Актуальность требует ручного ведения владельцем. Уже открытый гостевой календарь обновляется при повторном открытии страницы.

## API-контракт

- `GET /api/availability?apartment=<известный slug>` — публичный массив **только** `{startDate,endDate,status}`; неизвестная квартира — 404. Имена, контакты, реквизиты, ID владельца/записи и договоры не выдаются. Кэширование отключено.
- `GET /api/availability` — только после входа, периоды текущего владельца с ID для управления.
- `POST /api/availability` — сессия владельца, доверенный `Origin`, `application/json`. Строго `{catalogSlug,startDate,endDate,status}`. Даты — существующие календарные дни `YYYY-MM-DD`, начало не позже конца, максимум 367 дней включительно; `status` — `occupied` или `reserved`. У владельца должен существовать активный объект с этим slug. Возвращается созданная запись.
- `DELETE /api/availability` — та же защита, JSON `{id}`. Удаляется только собственная отметка. Успех `{ok:true}`, отсутствующая/чужая запись — 404.
- Ошибки: 400 валидация, 401 нет сессии, 403 неверный Origin, 404 неизвестная квартира/недоступная запись, 413/415 ограничения JSON, 500 отказ базы. Гостевой календарь показывает ошибку вместо ложной доступности.

`Availability` хранится в основной базе отдельно от неизменяемых договоров, FK на Admin с каскадным удалением при удалении администратора. Добавлены только новые таблица/индексы: миграция `202610300001_availability` для SQLite и PostgreSQL. Штатный production-init применяет её при публикации. Данные прежних таблиц не переписываются.

## Проверки

`npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npx playwright test`. Новые проверки охватывают реальные даты, включённый последний день, пересечения, сохранение языка, перевод кабинета, доступ владельца, CSRF и публичную приватность. Тестовые владельцы календаря выделены отдельно, чтобы совокупный набор не превышал лимит входов основного тестового аккаунта. Настоящая защита от перебора не ослаблялась. Реальные телефоны, нативные экранные дикторы и профессиональная языковая редактура требуют отдельной приёмки.
