# Подготовленный кабинет арендодателя

Кабинет объединяет предоставленные квартиры и сохранённый шаблон договора. Обычный путь: «Объекты» → поиск квартиры → «Создать договор» → арендатор, даты и общая сумма → предпросмотр → черновик → персональная ссылка и PDF.

## Квартиры

В карточках видны предоставленные фото, номер квартиры, подъезд, этаж, цена каталога и 2ГИС. Поиск работает по названию, адресу и номеру; архив отделён от действующих объектов. Цена каталога отделена от общей стоимости договора. Пока период тарифа не подтверждён, он явно отмечен как требующий уточнения; недостающая цена не заменяется нулевой.

«Добавить из каталога» выполняет защищённый POST `/api/catalog/import`: добавляет недостающие квартиры владельцу, не создаёт дубли, не перезаписывает ручные правки и не восстанавливает архив автоматически. Публичные карточки не получают приватные данные из кабинета.

## Шаблон договора

В разделе `/templates` один раз сохраняются ФИО/название арендодателя, ИИН/БИН, телефон, удостоверение, кем и когда оно выдано, а также условия договора. Правила проживания подготовлены по предоставленному образцу, включая запрет курения, тишину после 23:00, уборку и осмотр при выезде. Формулировки доступны для редактирования; это перенос предоставленного текста, а не его юридическое заключение.

Реквизиты сохраняются только в `Admin.contractDefaults` конкретного владельца, в JSON-строке. В репозитории находятся обезличенные условия; персональные сведения из исходного DOCX не включаются в исходники, seed, тесты или публичный каталог. Реквизиты попадут в конкретный договор и его PDF при создании; доступ к нему определяется существующей персональной ссылкой.

Новый договор получает копию текущего шаблона. Арендатор, квартира, даты и суммы в шаблон не сохраняются. В форме реквизиты арендодателя и условия можно раскрыть для разовой правки; редактирование шаблона не меняет существующие черновики и отправленные снимки. Необязательные поля удостоверения/адреса арендатора поддержаны в форме, HTML и PDF; старые документы без этих полей сохраняют совместимость.

## Локальная подготовка и очистка демоданных

Команда использует только локальную SQLite и владельца из `ADMIN_EMAIL`. Она намеренно отказывается работать в production и с PostgreSQL. Перед применением сохраните резервную копию базы и её sidecar-файлов при остановленном приложении.

```powershell
npm run db:generate
npm run db:migrate
npm run admin:prepare
npm run admin:prepare -- --apply
```

Без `--apply` команда показывает только количество объектов и режим, без записей. С `--apply` удаляет распознанные вымышленные объекты и их полностью вымышленные договоры/версии/ссылки/журнал; добавляет недостающие квартиры из каталога. Проверяются маркеры в имени, адресе, описании и каждом снимке. Если у демообъекта есть договор с реальными либо неизвестными данными, объект архивируется с сохранением всей истории. Другие владельцы и нераспознанные объекты не затрагиваются.

Для однократной подготовки частных реквизитов можно добавить `--defaults-file <локальный-json>`. Файл должен содержать поля схемы шаблона, храниться вне Git и не передаваться в публичный каталог. Команда проверяет данные до очистки и выводит только счётчики. Предоставленный DOCX извлекался отдельно в игнорируемый временный JSON; оригинальный файл не изменялся. Для дальнейших изменений используйте интерфейс `/templates`.

`npm run seed` остаётся отдельным демонстрационным инструментом, но пропускается, если у владельца уже есть объекты или договоры. Он не возвращает демоквартиры после подготовки рабочего кабинета.

## Безопасность и проверка

API шаблона и импорта требуют живую сессию владельца; изменяющие запросы — точный Origin. Шаблон проверяется строгой схемой, неизвестные поля отклоняются. Реквизиты хранятся в БД в открытом виде, как и содержание договоров; доступ к файлам, резервным копиям и аккаунту должен быть ограничен.

Проверяются очистка только подтверждённых демоданных, сохранение смешанной истории, изоляция владельцев, повторный импорт, валидация шаблона, перенос реквизитов/условий в договор и PDF, неизменность старых снимков, удобство формы и мобильная ширина. Источники проверок: `tests/admin-workspace.test.ts`, `e2e/admin-workspace.spec.ts` и существующие сценарии договоров.
