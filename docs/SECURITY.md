# Безопасность и ограничения

Для бесплатного облака подготовлены Render Free и Neon Free PostgreSQL. Секреты хранятся в конфигурации провайдера, автоматический первоначальный аккаунт создаётся только в пустой БД. Публичные ссылки используют HTTPS-origin Render. Транзакции договоров Serializable с ограниченным повтором P2034; внешняя приёмка и проверки сохранности после рестарта обязательны. Локальный SQLite и ключи в Git не передаются.

RentalSign — локальная демонстрация, не сервис ЭЦП. Никаких сертификатов, ключей НУЦ РК, государственных интерфейсов или юридически значимой подписи приложение не создаёт. Шаблон не проверен юристом. Seed и автотесты содержат только явные вымышленные данные, ИИН пустые, телефоны не предназначены для реальной отправки.

## Реализовано

- Пароли: scrypt со случайной солью и сравнение через timingSafeEqual. CLI требует 12–128 символов. Публичного пароля нет.
- Сессии: 256-битный случайный токен, SHA-256 в БД, HttpOnly/SameSite=Lax cookie; Secure в production. Срок проверяется сервером, logout удаляет запись.
- Права: requireAdmin в каждом административном Route Handler, requirePageAdmin в серверных страницах и layout. Все выборки/изменения привязаны к ownerId. ID случайные cuid, а не последовательные номера.
- CSRF: строгий Origin на каждом изменяющем маршруте, включая login/logout и публичное демоподписание. JSON Content-Type и ограниченный потоковый reader. SameSite — дополнительная мера.
- Валидация: строгие схемы Zod, длина/формат/диапазоны, даты, суммы и разрешённые значения. ИИН проверяется только по формату.
- XSS: пользовательское содержание выводится React как текст; dangerouslySetInnerHTML не используется. Базовая CSP, DENY frames, nosniff, no-referrer и запрет индексации.
- SQL: параметризованные запросы Prisma; пользовательский SQL не выполняется.
- Ссылки: 256-битный randomBytes token, SHA-256 для поиска, AES-256-GCM для сохранения возможности копирования. Отзыв и срок проверяются на каждом публичном действии/PDF. Новый URL отзывает предыдущий.
- Содержание: снимки версий, revision для конфликтов, отправленные и подписанные договоры не редактируются через приложение.
- Конкурентность: статус, signedAt и AuditEvent записываются в одной транзакции с условным переходом PENDING.
- Логи: только категория серверной ошибки, коды действий и ID договора. Ни тела запросов, ни персональные данные, ни токены не записываются приложением. Access-лог запросов Next.js dev отключён. Не включайте DEBUG Prisma с реальными данными.
- PDF: генерируется в памяти, не хранится в public; no-store и тот же контроль доступа, что для документа.
- Лимиты в SQLite: login — 5 попыток на хеш email за 10 минут, 100 глобально за 10 минут; публичные действия — 60 на токен за минуту, 600 глобально за минуту. Окна фиксированные; счётчик обновляется атомарно. Старые окна удаляются при создании новых.

## Принятые ограничения MVP

Bearer-ссылка даёт доступ любому её обладателю: пересылка ссылки равнозначна передаче доступа. Нет проверки личности клиента, второго фактора, captcha, подписания арендодателем, восстановления пароля, отдельных ролей или управления организацией. Нельзя трактовать timestamp, журнал или SHA-256 как подтверждение личности либо ЭЦП.

Глобальные лимиты могут блокировать всех клиентов при атаке. Для production нужны reverse proxy, доверенная обработка IP, распределённый limiter, защита от DoS и ограничение ресурсов. SQLite с локальным диском — один экземпляр сервера, без горизонтального масштабирования. Таблицы/поиск целиком загружаются для локального MVP; для больших объёмов нужна серверная пагинация.

CSP допускает inline-скрипты Next.js и inline-стили; nonce-based CSP следует внедрить и проверить отдельно для production. Dev добавляет unsafe-eval для инструментов разработки. RateBucket обеспечивает ограничение частоты, но не полную инфраструктурную защиту от перегрузки. Сессии по истечении недействительны, однако их записи не удаляются фоновым заданием.

Снимки неизменяемы через приложение, но владелец файлов базы может их изменить. contentHash не является внешним доказательством, подписью или WORM-хранилищем. Итоговый PDF генерируется из зафиксированного содержания по запросу; архив файла и криптографическая подпись отсутствуют.

Документы и персональные данные в SQLite не зашифрованы. Требуются ограничение доступа к ОС/файлам, политика хранения и удаления, защищённые резервные копии и юридическая оценка обработки данных до работы с реальными клиентами. `.env` и local-admin.txt содержат секреты локальной настройки: не передавайте их заказчику вместе с исходниками и не публикуйте.

Production требует HTTPS `APP_URL`, HTTPS перед Node.js, Secure cookies, менеджер секретов и исключение `/sign/*` из access-логов прокси/CDN/APM. Заголовок no-referrer уменьшает утечку ссылок, но история браузера и скриншоты могут их сохранить. Открывайте WhatsApp только по сознательному действию администратора.

## Зависимости

Установленные версии фиксируются package-lock.json. Prisma 6 выбрана для простой локальной SQLite-конфигурации; deepmerge-ts транзитивно заменён на 8.0.2 через npm overrides, затем миграции/тесты/сборка проверяются. `npm audit --omit=dev` следует запускать перед выпуском.

На текущей проверке `npm audit` сообщает об уязвимости braces через micromatch/fast-glob/ESLint Next (5 записей с учётом цепочки). Исправленной версии braces в registry пока нет; не используется на путях обработки входных данных приложения. Это остаётся ограничением цепочки инструментов разработки, а не причиной считать production подготовленным. Не запускайте инструменты с недоверенными glob-паттернами. Обновите зависимости и повторите полный audit перед production. См. [advisory GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
