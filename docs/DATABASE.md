# База данных

Облачная конфигурация поддерживает PostgreSQL: `npm run build:cloud` генерирует `prisma/postgresql/schema.prisma` из канонических локальных моделей. PostgreSQL использует отдельный каталог миграций, DATABASE_PROVIDER=postgresql и DIRECT_DATABASE_URL для миграций. Локальные команды продолжают использовать SQLite. См. DEPLOYMENT.md.

Источник схемы: `prisma/schema.prisma`, начальная миграция — `prisma/migrations/202610130001_init/migration.sql`. Локальный файл — `prisma/dev.db`; URL относительно prisma-каталога.

Миграция `202610180002_contract_defaults` добавляет nullable `Admin.contractDefaults`: проверяемая JSON-строка частных реквизитов и условий новых договоров. Поле не включается в публичный каталог или снимок целиком; каждый договор получает собственные значения. Изменение шаблона не обновляет сохранённые документы. Схемы SQLite и PostgreSQL синхронизированы, миграции добавочные.

| Модель          | Содержание                                                                                                         |
| --------------- | ------------------------------------------------------------------------------------------------------------------ |
| Admin           | Случайный cuid ID, уникальный email, scrypt-хеш, дата создания                                                     |
| Session         | Хеш случайного токена, adminId, срок действия                                                                      |
| Property        | ownerId, название, адрес, тип, номер, описание, rent/deposit, архив                                                |
| Contract        | Случайный ID, случайный номер, ownerId/propertyId, JSON-содержание черновика, статус, revision, createdAt/signedAt |
| ContractVersion | contractId, номер версии, неизменяемая JSON-строка snapshot, SHA-256 contentHash, createdAt/signedAt               |
| SigningLink     | versionId, уникальный tokenHash, encryptedToken, expiresAt/revokedAt                                               |
| AuditEvent      | contractId, код действия, категория ADMIN/CLIENT, серверное время                                                  |
| RateBucket      | Хешированный идентификатор окна, count, expiresAt                                                                  |

JSON хранится строкой для переносимости схемы между SQLite и PostgreSQL. Суммы — Int в целых тенге. Основные индексы: ownerId/createdAt, ownerId/archived, tokenHash, expiresAt, contractId/createdAt. Внешние ключи сохраняют связь версий с договором и предотвращают неявное удаление документов.

Миграция `202610180001_catalog_link` добавляет необязательный `Property.catalogSlug` и уникальную пару `(ownerId, catalogSlug)`; существующие записи получают NULL. Публичный каталог хранится отдельно от БД, импорт выполняется только владельцем по кнопке. Суммы нового импортированного объекта равны 0 до согласования; договор на такой объект требует положительную общую стоимость. Структура снимка PropertyInput не расширяется данными каталога.

Contract.status принимает `DRAFT/PENDING/DEMO_SIGNED/EXPIRED/REVOKED` на уровне приложения. `EXPIRED` обычно вычисляется по актуальной последней ссылке; хранимый статус может оставаться PENDING. Прямое изменение базы обходит инварианты приложения и не поддерживается.

Договор содержит копию данных объекта и сторон. Редактирование Property не изменяет отправленный ContractVersion. Перевыпуск ссылки добавляет версию; старые снимки и журнал сохраняются. Клонирование использует текущий действующий объект, создаёт DRAFT и новый номер; архивный объект сначала нужно восстановить.

## Миграции и резервные копии

`npm run db:generate`, затем `npm run db:migrate`. Для Windows setup предварительно создаёт пустой SQLite-файл, поскольку используемый schema engine может отказывать при его отсутствии. Для ручной настройки при такой ошибке создайте пустой файл по адресу DATABASE_URL и повторите migrate.

Перед переносом или резервным копированием остановите процесс приложения и сохраните файл базы (включая sidecar-файлы, если присутствуют). Отдельно сохраните TOKEN_ENCRYPTION_KEY в защищённом хранилище. Потеря ключа делает повторное копирование старых URL невозможным; выдача новых ссылок под новым ключом возможна и отзывает старые. База сама по себе содержит персональные данные в открытом виде: шифрование токенов не является шифрованием всей БД.

Для PostgreSQL создайте новые миграции, перенесите данные и проверьте конкурентность. Не пытайтесь применить SQLite SQL к PostgreSQL.


## Ручной календарь

Миграция `202610300001_availability` для обоих провайдеров добавляет `Availability`: id, ownerId (FK Admin), catalogSlug, startDate/endDate (YYYY-MM-DD), status (occupied/reserved), createdAt. Границы периода включены. Индексы по владельцу и slug/датам. Нет данных жильца и связи с неизменяемыми версиями договора. При удалении администратора его отметки удаляются каскадно. Публичный API выдаёт только даты и статус; подробности в [QUTTY_QONAQ.md](QUTTY_QONAQ.md).
