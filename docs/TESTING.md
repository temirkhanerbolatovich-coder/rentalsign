# Проверки

## Автоматические сценарии

Подготовленный кабинет: `tests/admin-workspace.test.ts` проверяет удаление только подтверждённых демоданных, сохранение смешанной/неизвестной истории и других владельцев, повторный импорт 7 квартир, частный шаблон и строгую валидацию, сохранение реквизитов и условий в независимом снимке и реальном PDF. `e2e/admin-workspace.spec.ts` проверяет защищённый редактор шаблона, сохранение/повторное открытие, поиск квартиры, фото и мобильную ширину, предвыбор квартиры и автозаполнение реквизитов, сохранение договора и PDF. Все реквизиты в тестах и скриншотах вымышленные.

Каждый прогон Playwright использует новую случайную `tmp/e2e-<id>.db`, чтобы прошлые тестовые квартиры и настройки не влияли на следующий прогон.

`npm test`: реальные сервисные операции на отдельной SQLite-базе. Проверяются статусы по времени, salted password hashes, CSRF, размер/формат JSON, URL encoding WhatsApp, сохранение черновика, шифрование токена, повторное чтение, подпись/журнал, повторная подпись, запрет изменения, expiry/revoke, неизвестные токены, отсутствие согласия, два одновременных запроса, доступ другого администратора, снимки после изменения объекта, revision conflicts, клонирование, архив, срок сессии, лимиты и длинный PDF.

`npm run test:e2e`: Playwright Chromium, отдельная база и сервер на 3100. Полный UI-сценарий: login → создание объекта → договор → предпросмотр → ссылка → WhatsApp URL и реальное Clipboard API → клиент на viewport iPhone → checkbox → demo → PDF → viewport Android → статус/журнал администратора → logout. Отдельно — анонимные API, неизвестные ссылки, login CSRF и неверный пароль.

Каталог: `tests/catalog.test.ts` проверяет 7 квартир/90 локальных WebP, цены и 2ГИС, четыре исправленные обложки по SHA256 и полные наборы фотографий по предоставленным исходникам, инструкцию видеодомофона, одновременный первый импорт без дублей, изоляцию владельцев, сохранение ручных правок, архив, положительную общую сумму договора и неизменяемый снимок. Сверка с пользовательской папкой `квартиры` пропускается, если её нет в чистой копии репозитория; проверка опубликованных данных и фото выполняется всегда.

`e2e/catalog.spec.ts`: поиск/цены/сортировка/пустой результат, неизвестная квартира → 404, мобильная галерея и загрузка фото, четыре исправленные карточки и 2ГИС, инструкция видеодомофона на публичной странице и в кабинете, анонимный импорт → 401, неверный Origin → 403, переход из карточки через вход к выбранному объекту, повторный импорт, обязательная итоговая сумма, сохранение черновика и запрет внешнего перенаправления. Снимки интерфейса сохраняются в игнорируемом `output/screenshots/`.

Мобильные тесты Chromium эмулируют размеры экранов, touch и user agent. Это не проверка реального iOS Safari, нативного WhatsApp или физических устройств. Сообщение никому не отправляется; проверяется только подготовленный URL.

## Облачные проверки

`scripts/check-cloud.ts` запускает реальные конкурентные операции в PostgreSQL: sign/sign, sign/revoke, sign/issueLink. Требует явного `CLOUD_SMOKE_ALLOW_WRITES=1`, создаёт отмеченные вымышленные записи. Загрузка облачной конфигурации и переключение Prisma-клиента описаны в DEPLOYMENT. Это дополнительная проверка провайдера, а не замена изолированных SQLite-тестов.

Внешняя приёмка проверяет фактический HTTPS-origin, Secure/HttpOnly cookie, CSRF, доступ без сессии, PDF, мобильное демодействие и сохранность существующих сессий/ссылок после повторного развёртывания. Пароли и bearer-токены не включаются в отчёт или Git; локальное состояние приёмки хранится в игнорируемом `tmp/`.

## PDF

Noto Serif Regular и Bold внедряются в PDF как FontFile2. Проверочные PDF с вымышленными данными находятся в `output/pdf`. Длинный текст должен содержать маркер `КОНЕЦ ДЛИННОГО ТЕКСТА`, финальную отметку деморежима и номера всех страниц. Проверяются поля старых снимков без необязательных реквизитов, все условия и различие предварительного и демоподписанного документа. Браузерный сценарий сохраняет реально скачанный PDF. Poppler позволяет отрисовать страницы:

```powershell
pdftoppm -scale-to 1200 -png output/pdf/long-demo-contract.pdf output/pdf/long-page
```

Для визуальной проверки смотрите все страницы, особенно переходы между страницами и подвал. Извлечение текста само по себе не доказывает отсутствие обрезания.

## Ручная приёмка перед показом

- Войти с аккаунтом из локального файла, пройти основной сценарий README.
- Обновить dashboard после действия клиента: данные приходят из базы, live push не реализован.
- Проверить чтение полного текста, скачивание предварительного и итогового PDF.
- Проверить на реальных устройствах iPhone/Safari и Android/Chrome, включая клавиатуру, увеличение текста и открытие WhatsApp.
- При показе по сети настроить доступный APP_URL. Origin браузера и сервера должны совпадать.
- Использовать только вымышленные данные, сохранять заметное демопредупреждение.

Фактический итог прогона записывается в `docs/ACCEPTANCE.md`; нельзя считать проверки на физических устройствах завершёнными по результатам эмуляции.
