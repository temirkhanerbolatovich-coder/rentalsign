## Основной UI-сценарий

Playwright выполнил вход → создание объекта → создание договора → предпросмотр → сохранение → генерацию ссылки → проверку URL WhatsApp → реальное копирование в Clipboard API → открытие клиентом без cookie → предварительный PDF → ознакомление → демоподписание → итоговый PDF → повторное подписание (409) → обновление статуса/журнала у администратора → попытку редактирования подписанного договора с валидным телом (409) → мобильную навигацию → выход → анонимный API (401).

Клиент проверен в Chromium с эмуляцией iPhone 13 и Pixel 7. У страницы клиента и мобильного dashboard отсутствует переполнение по ширине окна. Скриншоты находятся в игнорируемом `output/screenshots`.

Сервисные тесты отдельно подтверждают expired/revoked, неизвестный token, отсутствие согласия, два одновременных sign-запроса с ровно одним успешным событием, изоляцию владельцев, неизменность снимка после редактирования объекта, revision conflict, клонирование, архив, срок сессии и database limiter.

## Не проверено / не входит в MVP

- Физические iPhone/Safari и Android/Chrome, экранная клавиатура, VoiceOver/TalkBack и нативный запуск WhatsApp.
- Отправка реального сообщения: приложение лишь формирует URL, автотест никому не пишет.
- Доступ по внешней сети: для него нужен доступный APP_URL и отдельный HTTPS-хостинг.
- Production-инфраструктура, нагрузка, сторонний penetration test и работа с реальными персональными данными.
- Настоящая ЭЦП НУЦ РК, юридическая проверка, подпись двумя сторонами, биллинг и PostgreSQL.

Основной локальный демонстрационный сценарий подтверждён; оставшиеся пункты не следует выдавать за завершённую production-приёмку.
