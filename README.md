# Qutty Qonaq Apartments

MVP каталога квартир и оформления договоров аренды в Усть-Каменогорске. Публичный бренд — **Qutty Qonaq Apartments**, техническое имя репозитория и адрес хостинга остаются `rentalsign`.

**Сайт:** [rentalsign.onrender.com/apartments](https://rentalsign.onrender.com/apartments) · **Кабинет владельца:** [вход](https://rentalsign.onrender.com/login)

## Текущее состояние — 31 октября 2026

- 7 квартир, 90 фотографий, поиск по адресу, фильтр начальной цены, сортировка, галерея и ссылки 2ГИС.
- Русский, казахский и английский интерфейс: каталог, вход, кабинет и экран ознакомления. Выбор языка сохраняется.
- Логотип Qutty Qonaq без слогана, тёплая палитра, адаптивные карточки, шрифты Onest и Noto Sans, анимации с поддержкой уменьшения движения.
- Ручной календарь: владелец отмечает «Занято» / «Забронировано» в `/availability`; гость видит только даты и статус. **Неотмеченные даты не гарантируют доступность.** Реальные периоды нужно заполнять вручную.
- Объекты, шаблон, черновики договоров, неизменяемые отправленные версии, персональные ссылки, подготовка WhatsApp-сообщения и PDF.
- Интерфейс переводится; текст договора, данные владельца и PDF сохраняются в исходной редакции.
- Онлайн-бронирования гостями, оплаты и публичного WhatsApp-контакта владельца нет.

Подробнее: [текущие функции и календарь](docs/QUTTY_QONAQ.md), [шрифты и анимации](docs/INTERFACE_MOTION.md), [каталог](docs/CATALOG.md).

**Настоящая ЭЦП не используется. Демонстрационное действие не является подписанием ЭЦП. Шаблон не прошёл юридическую проверку.** Для публичной демонстрации используйте только вымышленные данные.

## Бесплатный сайт

Облачный MVP: [rentalsign.onrender.com](https://rentalsign.onrender.com). Next.js работает на Render Free, данные сохраняются в Neon Free PostgreSQL. Данные входа владельца находятся в игнорируемом `cloud-admin.txt`. Создавайте новые договоры на этом адресе: их персональные ссылки доступны извне. Локальные localhost-ссылки и база не переносятся автоматически. Ежечасное автопробуждение отключено; бесплатный сервис засыпает при простое; первый запрос может ждать около минуты. Подробности: [размещение](docs/DEPLOYMENT.md).

## Быстрый локальный запуск

Требования: Node.js 22 LTS или новее, npm, доступ к npm при установке. Проверено на Windows с Node.js 24.

```powershell
npm install
npm run setup:local
npm run admin:prepare -- --apply
npm run dev
```

Откройте http://localhost:3000. Email и случайно сгенерированный пароль находятся в **local-admin.txt**. Этот файл, `.env`, база и документы исключены из Git. Пароль не выводится в консоль. `setup:local` работает только при отсутствии `.env` и не перезаписывает существующие настройки. `admin:prepare -- --apply` добавляет 7 предоставленных квартир и очищает распознанные демоданные; перед очисткой существующей базы сохраните резервную копию. Реквизиты арендодателя задаются один раз в `/templates`. Для отдельной демонстрации `npm run seed` создаёт 3 вымышленных объекта и 5 договоров, только если у владельца ещё нет объектов и договоров.

Если настройка прервалась после создания `.env`, сохраните этот файл и выполните `npm run db:migrate`, затем `npm run admin:create` и `npm run seed`. Данные входа возьмите из своего локального `.env`. Не создавайте второй аккаунт с тем же email.

## Ручная настройка

1. Скопируйте `.env.example` в `.env`.
2. Задайте `DATABASE_URL`, `APP_URL`, `TOKEN_ENCRYPTION_KEY` (32 случайных байта в hex), `ADMIN_EMAIL` и `ADMIN_PASSWORD` (12–128 символов).
3. Выполните `npm run db:generate`, `npm run db:migrate`, `npm run admin:create`.
4. По желанию выполните `npm run seed`; запустите `npm run dev`.

Сгенерировать ключ можно командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`; сохраняйте его только в локальном `.env` или менеджере секретов. Пароль не передавайте аргументом CLI. `admin:create` создаёт аккаунт, но не сбрасывает существующий пароль. Переменные ADMIN_* нужны только CLI; после создания аккаунта их можно убрать из конфигурации сервера.

`APP_URL` должен точно совпадать с origin браузера, иначе CSRF-проверка отклонит операции. Для демонстрации на телефоне в локальной сети укажите доступный IP компьютера и порт в `APP_URL`, перезапустите сервер и используйте тот же адрес на компьютере. Копирование через Clipboard API на HTTP с IP может быть недоступно — поле ссылки можно выделить вручную. Для внешнего показа необходим отдельно настроенный HTTPS-хостинг; ссылки localhost работают только на том же компьютере.

## Основной сценарий

Квартиру также можно выбрать в каталоге: карточка → «Подготовить договор» → вход владельца → добавление объекта → форма с выбранной квартирой. Добавление выполняется только по кнопке, повторное действие не создаёт дубль и не заменяет правки владельца. Общую сумму за весь срок и депозит владелец указывает отдельно; каталог не бронирует даты. Арендатору вход не нужен: он получает персональную ссылку от владельца.

1. Войдите на `/login`.
2. Проверьте реквизиты и условия в `/templates`; они будут подставляться в новые договоры.
3. Выберите свою квартиру в `/properties`, нажмите «Создать договор», заполните арендатора, даты и общую сумму, проверьте предпросмотр и сохраните черновик.
4. В карточке договора задайте срок ссылки (1–720 часов) и подтвердите создание. После отправки содержание фиксируется.
5. Скопируйте ссылку или откройте подготовленное сообщение WhatsApp. Отправку сообщения выполняет сам администратор.
6. Откройте ссылку в отдельном браузере без регистрации, прочитайте условия и скачайте предварительный PDF.
7. Подтвердите ознакомление и демоподписание. Клиент получит итоговый демо PDF, администратор — статус и событие в журнале. Обновите карточку или обзор, чтобы увидеть новое состояние.

Отправленное содержание не редактируется. Для изменения создайте новый договор на его основе. Новая ссылка на тот же договор отзывает предыдущую и сохраняет ещё один снимок. Истекшие и отозванные ссылки не дают доступа к содержанию, включая PDF. После истечения ссылки итоговый PDF остаётся доступен администратору.

## Проверки

```powershell
npm run typecheck
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
npm run build
npm audit --omit=dev
```

Сервисные тесты используют отдельную случайную SQLite-базу в `tmp/`. Playwright запускает отдельный сервер на порту 3100 и новую случайную базу `tmp/e2e-<id>.db` для каждого запуска, использует временный случайный пароль; рабочую базу не изменяет. Трассы браузера отключены, чтобы не сохранять персональные URL и тела запросов. В `output/` остаются только вымышленные проверочные PDF и скриншоты; каталог исключён из Git.

`npm run build` проверяет production-сборку. Для `npm start` настройте HTTPS и HTTPS-origin в `APP_URL`: production-сессии используют Secure cookie, а сервер отклоняет HTTP-origin. Production-развёртывание этим проектом автоматически не выполняется.

## Стек и устройство

Next.js App Router / Route Handlers, TypeScript, Tailwind CSS, локальные компоненты shadcn/ui с Radix, Lucide, Prisma 6 (SQLite локально / PostgreSQL в облаке), Zod, PDFKit + встроенные Noto Serif Regular/Bold (SIL OFL). Пароли: scrypt; сессии: случайный токен с хешем в БД и HttpOnly cookie. Подписание вынесено в `SigningProvider` / `DemoSigningProvider`.
